# Naive Bayes, Text Classification, and Sentiment

Classification is a central task in NLP
1. Text categorization-- assign a label to entire text or document
	1. Sentiment analysis-- text categorization into positive or negative orientation
	2. Spam detection-- where the categories are spam and not spam
	3. Language id
	4. Authorship attribution
	5. Topic modeling (in fact, this was the task for which naive Bayes algorithm was invented)
Occurs at the sub-document level as well
1. POS tagging, period disambiguation, tokenization (deciding if char should be a word boundary)
	1. Even LM-- each word is a class, classify the next word based on the context so far

Classification can be done by hand with human-written rules, but rules are often broken and change over time. So we usually use **supervised machine learning** where we have a dataset of input observations and corresponding "correct outputs" from which the machine makes inferences about new observations. Formal definition:
1. Take an input $x$ and a fixed set of output classes $Y= \{y_1, y_2... y_M\}$ and return a predicted class $y \in Y$. 
2. Sometimes for text classification we use $d$ document for $x$ and $c$ class for $y$ 
3. In the supervised setting we have training set of $N$ documents that have been labeled with a class $\{(d_1, c_1), (d_2, c_2), ... (d_N, c_N)\}$ 
	1. In which we learn a classifier that maps a new document to a class $c \in C$ 
	2. A **probabilistic classifier** additionally tells the probability of that assigned class

**Generative** classifiers like naive Bayes determine which class was most likely to have generated the observation. 

**Discriminative** classifiers like logistic regression determine which features from the input are most likely to discriminate between the possible classes. This type is more commonly used. 

## Naive Bayes Classifiers 

**Multinomial naive Bayes classifier** makes a naive/simplifying assumption about how features interact. 
$$c\hat{} = \text{argmax}_{c \in C}  P (c|d)$$
That is, the predicted class $c\hat{}$ is the value of $P(c|d)$ where $c \in C$ maximizes that probability. 

**Bayesian inference** uses Bayes' rule to transform the above into other probabilities. Bayes' rule is:
$$P(x|y) = \frac{P(y|x)P(x)}{P(y)}$$
Substituting back into the first equation, dropping the denominator because $P(d)$ is the same for all classes, since it's the same document, and doesn't affect the classification. 

$$ c\hat{} = \text{argmax}_{c \in C} P(c|d) = \text{argmax}_{c \in C} P(d|c)P(c)$$

Generative model, since the above equation basically says, sample a class from $P(c)$, then words are generated by sampling from $P(d|c)$. 
1. $P(d|c)$ is the likelihood of the document 
2. $P(c)$ is the prior
3. WLOG we can represent a document as a set of features, and the equation becomes $$c\hat{} = \text{argmax}_{c \in C} P(f_1, f_2,...f_N|c)P(c)$$
4. Even that is too complicated to compute. So we make two simplifying assumptions
	1. Bag of words assumption-- assume position doesn't matter. So $f_1...f_N$ encode word identity not position
	2. Naive Bayes assumption-- conditional independence, assume each $P(f_i|c)$ is independent 
	3. So then the equation becomes: $$c_{NB} = \text{argmax}_{c \in C} P(c)\prod_{f \in F} P(f|c)$$
	4. To apply this to a text, use each word in the doc as a feature, then walk through each word position in the doc
	5. Also, do all probabilities in the log space to increase speed and avoid underflow
		1. Makes the class prediction as a linear function of the input features, ie linear combos of inputs, hence a **linear classifier** 

## Training Naive Bayes Classifier 

For the class prior, we need the number of docs in class $c$ divided by the total number of docs: 

$$\hat{P}(c) = \frac{N_c}{N_{doc}}$$
For the probability of a feature $f_i$ given $c$ (assuming the feature is just the existence of the word in the doc's bag of words), we concatenate all the docs in class $c$ and take the frequency of $w_i$ out of the total number of words:

$$ \hat{P}(w_i|c) = \frac{count(w_i, c)}{\sum_{w \in V}count(w,c)}$$
where $V$ is all words in the vocabulary, not just the ones in class $c$.

But what if one word doesn't occur in class $c$ at all, but does occur in a different class? Then it will have probability of 0 and zero out the entire product. We use **Laplace smoothing** and add one to each numerator and denominator. 
$$ \hat{P}(w_i|c) = \frac{count(w_i, c) + 1}{\sum_{w \in V}count(w,c) + 1} = \frac{count(w_i, c) + 1}{(\sum_{w \in V}count(w,c))+ |V|}$$ 
For **unknown words** that occur in test data but not training data, we can just discard them. Some systems also remove **stop words** like *the* and *a*. These can be predefined or sorted and removed by top 10-100 in frequency. Stop words are removed from both the training and test data.

## Optimizing for Sentiment Analysis

1. Binary Multinomial Naive Bayes/ Binary Naive Bayes-- same algorithm but maxes the counts at 1 (since the word occurring at all is most important in sentiment analysis, not how often it occurs)
	1. Remove all dup words before concatenating them into the big doc, also remove from test docs
	2. So the count just tells you how many docs it occurred in, not the total number of occurrences
2. Negation-- whenever a negation word occurs, prepend NOT to all the next words until the next punctuation. so "didn't like this movie, but" becomes "NOT_like NOT_this NOT_movie, but"
3. Sentiment Lexicons-- premade dataset that labels words based 
	1. Add a feature that is counted whenever a word from the positive lexicon occurs, rather than counting them separately
	2. Better to use dense lexicon features rather than sparse individual word features when the training data itself is sparse or nonrepresentative

## Evaluation: Precision, Recall, F-measure

1. For each doc, we need human labels called **gold labels** and the label assigned by the model
2. **Confusion Matrix** 
	1. precision = $\frac{\text{tp}}{\text{tp}+ \text{fp}}$
	2. recall = $\frac{\text{tp}}{\text{tp}+ \text{fn}}$ 
	3. accuracy = $\frac{\text{tp} + \text{tn}}{\text{tp}+ \text{fp} + \text{tn} + \text{fn}}$
	4. Way of measuring how well the system performs compared to the gold labels
	5. Accuracy isn't as good a metric for classification tasks, cause some classes may be way bigger (ie if one class was way bigger, accuracy would be high even if it never selected the smaller class)
3. **F Measure** is a single metric that incorporates precision and recall
	1. Weighted harmonic mean, which favors the smaller of the two values, which is more conservative estimate
	2. $$F_{\beta} = \frac{(\beta^2 + 1)\text{PR}}{\beta^2\text{P} + \text{R}} $$
	3. $\beta^2$ parameter weights recall vs precision, with $\beta > 1$ favoring recall, and $\beta < 1$ favoring precision (we usually choose $\beta = 1$)

### Evaluating with 2 or more classes

1. Naive bayes is already a multiclass classifier
2. Have to compute distinct precision and recall for each class
	1. Macroaveraging-- compute performance per class and then average over classes
	2. Microaveraging-- pool all the classes together and take the overall average 
	3. Macroaverage performs better since microaverage favors large classes
## Test sets and Cross Validation

1. Training set to train model, development test set (or dev set) to tune parameters and decide which model is best. Then we run on an actual test set
2. What if we could use all data for training and testing? **cross validation** 
3. x-Fold cross validation-- partition into x sets, then train on x-1 of them and validate on the remaining one. Then repeat for all the sets as the test set
4. But we don't want to cheat by looking at the test set while training. So we do 10 fold cross validation on the training set and keep a separate test set.
